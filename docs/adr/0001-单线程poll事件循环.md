# 单线程 poll 事件循环

**Status**: accepted

客户端采用单线程 poll() 事件循环（监听 socket fd + STDIN_FILENO，200ms 超时），不使用 pthread；SIGINT 通过 volatile sig_atomic_t 标志配合 200ms 超时实现优雅退出（poll 最迟每 200ms 检查一次标志），SIGPIPE 忽略（send 侧另加 MSG_NOSIGNAL 双保险）。

选择单线程 + poll 而非镜像服务器的 epoll + 线程池：本项目的学习目标是理解"事件循环"这一概念本身——用最简单的手段（poll）走通"读流→增量解析→分发→写回"的完整链路，与服务器形成对照：服务器是多线程分工，客户端是单线程串行。200ms 超时而非阻塞等待，是为了让 SIGINT 标志能及时被观察到。

**Consequences**: 单线程意味着任何阻塞调用都会卡住整个循环——recv/send 使用阻塞 socket 时，对端拥塞（如 M4 大文件传输）会阻塞事件循环；后续若出现该问题，需引入非阻塞 socket + 写缓冲（镜像服务器的 client->write_buf 思路）。stdin 读取依赖终端 canonical 行缓冲模式，fgets 不会在 poll 报告可读后长阻塞；若将来改 raw 模式需自行实现行缓冲。Windows/MSVC 无 poll/unistd/MSG_NOSIGNAL，本决定限定客户端仅在 Linux/WSL 构建运行。
