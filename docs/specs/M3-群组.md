# M3 群组

## Problem Statement

客户端用户目前只能在大厅聊天与私聊。与 TCPServer 的多人协作聊天需要群组能力：创建群、加入群、离开群、向群内发送消息。客户端缺失对应的命令与帧分发，群组功能完全不可用。

## Solution

新增 4 个命令：`/gcreate <群名>`、`/gjoin <群名>`、`/gleave <群名>`、`/gmsg <群名> <消息>`，分别映射 MSG_GCREATE / MSG_GJOIN / MSG_GLEAVE / MSG_GMSG 帧；接收侧新增 MSG_GMSG 帧分发（服务器已格式化 `[群名] 发送者: 消息`，原样打印）。创建/加入/离开的服务器反馈均为 MSG_SERVER_MSG 公告或 MSG_ERROR 错误帧，复用现有显示逻辑，零新增 UI 概念。

## User Stories

1. 作为已登录用户，我想创建群组 `/gcreate 学习小组`，以便邀请他人加入一个独立的聊天空间
2. 作为创建者，我想收到创建成功的确认（`Group '学习小组' created. You are the first member.`），以便确认群组已建立
3. 作为用户，我想在创建重名群时收到 `错误(203): Group already exists`，以便知道该群名已被占用
4. 作为用户，我想在创建空名或超长（≥32 字符）群时收到错误提示，以便避免无效请求
5. 作为用户，我想加入他人创建的群 `/gjoin 学习小组`，以便参与群内讨论
6. 作为用户，我想在加入不存在的群时收到 `错误(201): Group not found`，以便及时纠正群名
7. 作为用户，我想在重复加入同一群时收到 `错误(202): Already a member of this group`，以便了解我的成员状态
8. 作为群成员，我想在有人加入时看到公告（`bob has joined group '学习小组'`），以便感知群成员变化
9. 作为用户，我想向群内发消息 `/gmsg 学习小组 今天学什么`，以便进行群组讨论
10. 作为群成员，我想收到群内广播 `[学习小组] alice: 今天学什么`（含发送者本人的回显），以便看到完整的群对话
11. 作为非成员，我想在向群发消息时收到 `错误(201): You are not a member of this group`，以便知道无权发言
12. 作为成员，我想在向不存在的群发消息时收到 `错误(201): Group not found`，以便纠正群名
13. 作为群成员，我想离开群 `/gleave 学习小组`，以便不再接收该群消息
14. 作为离开者，我想收到 `You have left group '学习小组'` 确认，以便知道离开成功
15. 作为剩余成员，我想在有人离开时看到公告（`bob has left group '学习小组'`），以便感知成员变化
16. 作为最后一名离开者，我想收到 `Group '学习小组' has been deleted (last member left)`，以便知道群组已解散
17. 作为非成员，我想在离开群时收到 `错误(201): You are not a member of this group`，以便知道我的成员状态
18. 作为用户，我想在 `/gcreate` `/gjoin` `/gleave` 缺少群名时看到用法提示，以便不发出无效请求
19. 作为用户，我想在 `/gmsg` 缺少群名或消息时看到用法提示，以便不发出无效请求
20. 作为用户，我想在 `/gmsg` 使用超长群名（≥32 字符）时被本地拒绝，以便不发送必然失败（或错群）的请求
21. 作为用户，我想在 `/help` 中看到群组命令说明，以便发现群组能力
22. 作为已登录用户，我想在断连/退出时被自动移出所有群（服务器静默清理），以便无需手动退群
23. 作为聊天用户，我想群组消息与大厅/私聊消息在终端中同样不打断输入行地显示，以便保持一致的阅读体验

## Implementation Decisions

- **模块**：commands 模块新增 4 个命令分支（单参命令 /gcreate /gjoin /gleave 内联解析；/gmsg 经纯函数解析）；app 模块帧分发新增 MSG_GMSG case；ui 模块更新帮助文本；协议层零改动（text1/text2 构造器已覆盖）；术语表新增群组/群聊消息/群组成员术语。
- **命令协议契约**（载荷与服务器 server.c/group.c/chat.c 一致，服务器为唯一权威）：
  - `/gcreate <群名>` → MSG_GCREATE：`group_name`（text1）
  - `/gjoin <群名>` → MSG_GJOIN：`group_name`（text1）
  - `/gleave <群名>` → MSG_GLEAVE：`group_name`（text1）
  - `/gmsg <群名> <消息>` → MSG_GMSG：`group_name\0message`（text2）
- **S→C 形态**：群聊广播 `[群名] 发送者: 消息`（含发送者本人，同大厅广播的预期回显）；创建/加入/离开反馈全部是 MSG_SERVER_MSG 公告或 MSG_ERROR 错误帧，原样打印，不区分处理。
- **纯函数接口**：`commands_parse_gmsg(line, group, group_sz, &msg)`——与 M2 `commands_parse_priv` 同构（首个空白前为群名、其后为消息、消息内部空格保留、群名超长拒绝），群名长度上限 MAX_GROUP_NAME_LEN-1（31，服务器以 ≥32 拒绝）。单参命令不抽纯函数。
- **参数解析规则**：命令后多余空白跳过；单参命令参数为空 → 用法提示；/gmsg 缺消息 → 用法提示。
- **错误显示**：所有群组错误（201/202/203）走既有 MSG_ERROR 分支（`错误(码): 消息`），零新增。注意服务器对空名/超长名也统一报 201，客户端原样显示。
- **断连清理**：服务器在客户端断开时自动移除其群成员身份（静默，无公告），客户端零处理。

## Testing Decisions

- **原则**：只测外部行为——解析纯函数的输入→输出映射；不测实现细节（不做 mock 连接/帧发送）。
- **单元测试**：test_commands 目标新增 `commands_parse_gmsg` 用例（黄金切分、多空白、内部空格保留、缺群名、缺消息、超长群名拒绝）——与 M2 parse_priv 用例同构，先例 `tests/test_commands.c`（无框架 CHECK 宏，ctest 注册）。
- **e2e**：真实服务器 + 多客户端冒烟——alice 创建群 → bob 加入 → 双向群聊（含发送者回显）→ 非成员发消息被拒 → bob 离开 → 最后一人离开后群删除提示；错误场景（重名/重复加入/群不存在）。脚本先例 `Temp/e2e_m2.sh`（管道驱动 + 日志对比）。
- **不做**：协议构造重复测试（text1/text2 黄金字节已覆盖）；分发逻辑单测（trivial 原样打印，e2e 覆盖）。

## Out of Scope

- 群组列表查询、邀请、踢人（服务器无对应协议）
- 群主/成员权限分级（服务器无此概念，创建者无特权）
- 离线群消息（服务器不缓存群消息，仅私聊缓存）
- 群名修改、群公告
- 断连离开的公告（服务器静默清理，无广播）
- M4 文件传输、M5 ncurses TUI

## Further Notes

- 群组里程碑延续 M2 扩展点：app 分发 switch + commands 命令分支；协议以 TCPServer 源码为唯一权威，客户端零服务器改动。
- 已知服务器 bug（2026-08-08 记录，未修）不影响本里程碑：disconnect 广播不唤醒通知 fd，`has left` 公告可能滞留——但群组离开公告由显式 /gleave 触发（走 dispatch cleanup 唤醒），不受影响。
- e2e 中群名与消息均可用中文（UTF-8，服务器按字节处理）。
- 术语表同步：CONTEXT.md 新增「群组」「群聊消息」「群组成员」条目（含行为规则：广播含发送者本人回显是预期行为；群组销毁条件=成员数为 0）。
